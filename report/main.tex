\begin{abstract}
This report presents a verified DeFungi image-classification study using 9,114 RGB JPEG images from five fungal classes. A deterministic stratified split was used with 6,379 training images, 1,367 validation images, and 1,368 test images. All custom models operated on 64$\times$64 inputs. Model A, a standard convolutional neural network with 101,829 trainable parameters, achieved 0.6959 test accuracy. Model B, a lightweight depthwise-separable CNN with 14,272 trainable parameters, achieved 0.6484 test accuracy while reducing parameters by 85.98\% and serialized model size by 82.33\% relative to Model A. Two ImageNet transfer-learning models were also evaluated on the same sample membership at 64$\times$64 input: MobileNetV2 achieved 0.6908 test accuracy and EfficientNet-B0 achieved 0.7668. The final comparison shows that EfficientNet-B0 gave the highest measured accuracy, while Model B had the smallest disk footprint, lowest included MAC estimate, and lowest measured CPU batch-1 latency. The results therefore show a practical trade-off: transfer learning improves accuracy, but the custom lightweight model is more attractive when memory and CPU latency are the dominant constraints.
\end{abstract}

\section{Introduction}
Edge image-classification systems often need to balance accuracy against memory, computation, and latency. The purpose of this assignment was to design and evaluate convolutional neural networks for a resource-constrained DeFungi classification task, then compare the custom models with lightweight pretrained architectures.

The work was organized around four model families. Model A used standard convolution layers and acted as the stronger custom baseline. Model B used depthwise-separable convolution to reduce the parameter count below the assignment target of 100,000 parameters. MobileNetV2 \cite{sandler2018mobilenetv2} and EfficientNet-B0 \cite{tan2019efficientnet} were evaluated as lightweight state-of-the-art transfer-learning alternatives. All results reported here come from saved project artifacts only; no report value is taken from a rerun or from an external group report.

\subsection{\texorpdfstring{64$\times$64 Input}{64x64 Input}}
The assignment required compact image inputs for a resource-constrained setting. The custom data pipeline therefore resized all images to 64$\times$64 with three channels and normalized pixel values to $[0,1]$. The Session 3 transfer-learning runs also used 64$\times$64 input because both requested ImageNet backbones loaded correctly at this resolution. This preserves consistent sample membership and avoids silently switching to a larger ImageNet input size.

\subsection{Stratified 70/15/15 Split}
A deterministic stratified split was created once using seed 42. The split proportions were approximately 70\% training, 15\% validation, and 15\% test for each class. The saved verification files report 9,114 unique paths, no duplicate split paths, and the split counts shown in Table~\ref{tab:dataset_split}. The test set was used only for final evaluation.

\subsection{Preprocessing and Augmentation}
For custom CNN training, images were decoded as RGB, resized to 64$\times$64, converted to floating point, and scaled by $1/255$. The saved training evidence does not depend on a new split or on test-time selection. For pretrained models, the same split membership was used, but the Keras preprocessing function associated with each backbone was applied. MobileNetV2 used \texttt{mobilenet\_v2.preprocess\_input}; EfficientNet-B0 used the Keras EfficientNet preprocessing entry point recorded in the metrics file.

\subsection{Depthwise Separable Convolution}
For a standard convolution with kernel size $K_h\times K_w$, $C_{in}$ input channels, $C_{out}$ output channels, and one bias per output channel, the parameter count used in this project is
\begin{equation}
P_{\text{std}} = (K_hK_wC_{in}+1)C_{out}.
\end{equation}
For Keras \texttt{SeparableConv2D} with bias enabled, the saved implementation uses one depthwise spatial kernel per input channel, a 1$\times$1 pointwise convolution, and one bias per output channel:
\begin{equation}
P_{\text{sep}} = K_hK_wC_{in}+C_{in}C_{out}+C_{out}.
\end{equation}
The reduction percentage is
\begin{equation}
R = \frac{P_{\text{std}}-P_{\text{sep}}}{P_{\text{std}}}\times100\%.
\end{equation}

\subsection{Parameter Calculation}
The full-model parameter reduction from Model A to Model B is 87,557 parameters:
\begin{equation}
\frac{101829-14272}{101829}\times100 = 85.98\%.
\end{equation}
This reduction is mostly due to replacing expensive spatial convolution kernels with depthwise and pointwise operations in Model B.

\subsection{Hardware-Aware Activation Selection}
Both custom models used ReLU in hidden layers. ReLU is appropriate for hardware-aware design because it mainly computes $\max(0,x)$ and does not require exponentials. The output layer used softmax because the task is single-label five-class classification.

\section{Optimizer Selection and Tuning}
\subsection{SGD}
The controlled optimizer pilot included stochastic gradient descent with learning rate 0.01. It reached a final validation loss of 1.4039 after five pilot epochs.

\subsection{SGD with Momentum}
Momentum adds a velocity term that accumulates previous updates:
\begin{align}
v_t &= \mu v_{t-1} - \eta \nabla_\theta J(\theta_t),\\
\theta_{t+1} &= \theta_t + v_t.
\end{align}
The momentum pilot used $\mu=0.9$ and learning rate 0.01. It reached a final validation loss of 1.3385.

\subsection{Selected Adaptive Optimizer}
Adam \cite{kingma2015adam} was the selected adaptive optimizer. The pilot used learning rate 0.001 and reached the lowest final validation loss among the tested optimizers.

\subsection{Experimental Comparison}

\section{Custom CNN Training and Evaluation}
\subsection{Training Setup}
Model A and Model B were trained for 20 epochs with batch size 32 on the fixed DeFungi split. The validation set was used during training monitoring, and the test set was used only for final reported metrics. Accuracy, macro precision, macro recall, and macro F1 were computed from the saved test predictions.

For a test set of $N$ samples, accuracy is
\begin{equation}
\text{Accuracy} = \frac{1}{N}\sum_{i=1}^{N}\mathbf{1}(\hat{y}_i=y_i).
\end{equation}
Macro precision and macro recall average per-class precision and recall equally across the five classes:
\begin{align}
\text{Macro Precision} &= \frac{1}{C}\sum_{c=1}^{C}\frac{TP_c}{TP_c+FP_c},\\
\text{Macro Recall} &= \frac{1}{C}\sum_{c=1}^{C}\frac{TP_c}{TP_c+FN_c}.
\end{align}

\section{Lightweight State-of-the-Art Models}
\subsection{MobileNetV2}
MobileNetV2 uses inverted residual blocks and depthwise separable convolutions to reduce computation while preserving representational capacity \cite{sandler2018mobilenetv2}. In this project, the ImageNet pretrained MobileNetV2 feature extractor was adapted to a five-class DeFungi head.

\subsection{EfficientNet-B0}
EfficientNet-B0 is the baseline EfficientNet model family member, designed around compound scaling of depth, width, and resolution \cite{tan2019efficientnet}. The project used ImageNet pretrained weights and replaced the classifier with a five-class DeFungi head.

\subsection{Transfer-Learning Strategy}
Both pretrained models used a two-stage transfer-learning strategy. Stage 1 froze the feature extractor and trained the new classifier head for three epochs. Stage 2 fine-tuned an upper subset of the backbone with a smaller learning rate. Validation loss selected the saved checkpoint, and the test set was not used for model selection.

\subsection{Edge Deployment Trade-offs}
There is no single universally best model in the verified results. EfficientNet-B0 is the accuracy leader, but it has the largest parameter count, largest serialized model, and slowest measured CPU latency. Model B is the resource leader, but its accuracy is lower than Model A and EfficientNet-B0. For a very tight memory or latency budget, Model B is the strongest candidate among the measured models. For a less constrained device where accuracy matters more than disk footprint and CPU latency, EfficientNet-B0 is more attractive.

\section{Discussion}
The custom-model comparison shows the intended effect of depthwise-separable convolution clearly. Model B reduced parameters by 85.98\%, serialized size by 82.33\%, and the included MAC estimate by 88.81\% compared with Model A. Its CPU mean latency also decreased, but only by 43.62\%. Therefore, the empirical runtime result follows the same direction as the MAC reduction, but not the same scale.

The accuracy cost of the lightweight custom design was measurable. Model A reached 0.6959 accuracy, while Model B reached 0.6484. This difference is consistent with Model B having fewer channels and fewer trainable parameters. The confusion matrices show that H1 was generally easier because it is also the largest class. H2 was often confused with H1 by all models. H3 was especially weak for the custom models, while EfficientNet-B0 improved H3 recall to 0.8130.

The pretrained models show the benefit and cost of transferred ImageNet representations. EfficientNet-B0 improved the best custom accuracy by 0.0709 absolute accuracy. However, the serialized EfficientNet-B0 model was 32650.04 KiB, compared with 219.41 KiB for Model B. MobileNetV2 did not outperform Model A in this run, but it still had a much larger serialized footprint and much higher measured CPU latency than both custom CNNs.

Parameter count alone should not be used as a complete edge-performance claim. It does not directly measure RAM usage, cache behavior, kernel launch overhead, implementation quality, or energy. MAC estimates also exclude operations such as activation functions, pooling, normalization, and memory movement. The CPU latency measurements are useful for comparing these saved Keras models on this computer, but they are not microcontroller measurements.

The main limitations are the use of a single split, a single seed, limited hyperparameter search, possible class imbalance, and no physical edge-device energy measurement. The transfer-learning results also rely on external ImageNet prior knowledge. Finally, 64$\times$64 input is much smaller than standard ImageNet transfer-learning practice, so the pretrained models were intentionally evaluated under an assignment-consistent but resolution-constrained interpretation.

\section{Conclusion}
The assignment objective was achieved using verified DeFungi artifacts. Model A provided the strongest custom CNN accuracy, while Model B satisfied the lightweight design goal with 14,272 parameters and the smallest measured resource footprint. EfficientNet-B0 achieved the best overall accuracy, but with the largest serialized model and highest CPU latency among the four evaluated models. The final recommendation depends on deployment priorities: Model B is the most appropriate measured option for tight memory and latency constraints, while EfficientNet-B0 is preferable when accuracy is the dominant requirement and the platform can support the extra resource cost.
